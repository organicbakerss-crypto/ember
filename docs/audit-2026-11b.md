# Audit 2 and speed check, November 2026

The whole app was driven again, scripted with screenshots, on a library built to be the size of a serious web serial:

- **The story:** 3 books, 90 chapters, about 196,000 words.
- **The world:** 300 entries with pages, facts and tags, 40 portraits, 200 relationships and an 8 MB map.

Every screen was timed, along with every background request (first call and repeat). Typing was timed from key to screen. "Frozen" means the time the screen could not respond at all (long tasks).

Every timing was taken twice:

- in the **built app** (what an installed app runs);
- in **`npm run dev`** (how it's run today).

Nothing crashed and no screen logged an error.

**The 10–15 s wait when opening the world beside didn't reproduce here** (0.6–0.8 s). The likeliest causes:

- **Running with `npm run dev`.** Dev mode is 2–3× slower everywhere. It loads every screen twice on purpose (React's strict mode). It also builds code the first time it's used.
- **Something in the real library this test doesn't have,** for example a large map with many regions, or many large pictures.
- **A slower computer or disk.** Every slow request above reads every file it needs from disk, every time.

Section 1 of the plan adds a speed log in the app, so the real cause on your computer can be measured instead of guessed.

### Why things are slow (from reading the code)

1. **No memory between requests.** Opening the world re-reads all 300 entry files, the maps, relationships and inbox, and re-scans every entry page for names. It then does it all again after **every** change in the world (`useWorld` reloads everything on each `library:changed`). The name catcher, AI summaries, publishing list and story search each re-read every chapter of the story.
2. **Saves grow with the book.** Each save rewrites the book's manifest (the file list sync uses), so a save in a 30-chapter book costs more than in a 3-chapter one. Building the test library, book three saved more than twice as slowly as book one.
3. **The Manuscript lays out the whole book at once.** It builds one editor for 30 chapters, then measures every line of every page before showing anything (2–6 s frozen).
4. **Book mode lays out every chapter up front.** Then every visible page renders its whole chapter again.
5. **Every key press does whole-chapter work.** Scenes, comments, word count and stats each walk the entire chapter on each key, and the analysis highlights recompute on top. That's fine in the built app, but it shows in dev mode as 45–160 ms per key.
6. **One 2.6 MB bundle for every screen.** The map, board, Book, AI and settings code all load at start, even when they're never opened.
7. **Pictures are used at full size.** A 512-pixel portrait is drawn at 40 pixels. The 8 MB map is decoded in full before anything shows: the Where lens is an empty grey box for 1–3 s, with no loading sign.

## 2. Broken or wrong

1. **The people board is unreadable with many people.** 195 portraits in one ring, labels on top of each other, 200 lines through the middle.
2. **An entry whose kind isn't known silently counts under How.** For example a kind from a template that was deleted. It should be visibly "Other" or "Unknown kind".
3. **The big map shows as an empty grey box** for a few seconds, with no sign that it's loading.

## 3. Not intuitive

1. **World search results push everything down.** The lenses (Where / Who / When / How) drop off screen, and the side panel gets a sideways scrollbar.
2. **The top of the writing view is crowded:** ⋯, Manuscript, Book, World beside, Write/World. "World beside" is drawn bigger than the buttons next to it. Manuscript and Book are two ways of viewing the same book; they'd read better as one switch: **Page · Manuscript · Book**.
3. **When → "Not on the timeline yet"** gives every event a full-width "Place it…" dropdown. With 25 events it's a wall of dropdowns.

## 4. Clutter

1. The When list above.
2. The board above: with no filter, every person and every line shows at once.

## 6. Stress test: 2.84 million words

The test library behind this section:

- 30 books and 750 chapters, about 2.84 million words in all;
- a world of 1,000 entries, 100 portraits and 600 relationships;
- one book that is a **size ladder**: single chapters of 500 to 100,000 words.

All timings are in the built app.

| ------------ | ----------- | -------------------- | --------------------- | ------------------------------ |

| 5,000        | 0.16 s      | 0.20 s               | 9 / 21 ms             | 0.06 s                         |
| 10,000       | 0.23 s      | 0.22 s               | 11 / 31 ms            | 0.15 s                         |

**More text does slow things down, almost in a straight line, and one cause dominates.** A profile of opening a 30,000-word chapter shows about 1 of the 1.1 seconds is page-break layout. It finds where every line of the chapter starts, one line at a time, with an expensive browser call per line. It runs twice on opening, and again at every pause in typing. Saving is fine at any size (0.05 s at 100,000 words).

**Library size slows down everything that reads the whole story:**

| Request (2.84M words)                                            | Time        |
| ---------------------------------------------------------------- | ----------- |
| Bookshelf list (rebuilt after every new chapter, rename or move) | 1.1 s       |
| Name catcher (inbox)                                             | 3.4 s       |
| Publishing list                                                  | 2.3 s       |
| AI summaries list                                                | 2.2 s       |
| Find in the whole story                                          | 1.7 s       |
| "Where does this name appear" index (first time)                 | 2.8 s       |
| World (1,000 entries)                                            | 0.56–0.67 s |

**Building the test library showed the same thing.** Adding a 25-chapter book took 4 s when the library was small, and 40 s when it held 2.7 million words. Each new chapter rebuilt the bookshelf, which re-reads every chapter to count words.

**Manuscript and Book mode** of a 100,000-word book: 6.6 s and 6.3 s with the screen frozen.
